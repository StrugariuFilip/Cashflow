# CashFlow

**CashFlow** is a full-stack web application for managing personal finances. Users can create an account, record income and expenses, and view their current balance, totals, and spending by category on a dashboard.

> Developed as a personal finance project for the Computer Engineering program at USV.

## Features

**Authentication**
- Email and password registration; passwords are stored as Argon2 hashes
- JWT authentication and local logout by removing the token
- Automatic session expiration when the token expires
- Application pages are accessible only to authenticated users

**Transactions**
- Create, edit, and delete transactions with a type (income / expense), amount, category, date, and optional description
- Transaction history displayed in chronological order
- Each user can view and modify **only their own transactions**

**Dashboard**
- Total income, total expenses, and current balance
- Recent transactions
- Monthly comparison and spending by category

**Planned** — filtering by category or date and CSV export.

## Installation and Running

### Prerequisites

- Python 3.15
- Node.js 20+ and npm
- PostgreSQL (running locally)

### 1. Database

Create an empty database, for example from `psql`:

```sql
CREATE DATABASE cashflow;
```

### 2. Backend

From the repository root:

```powershell
py -3.15 -m venv .venv
.\.venv\Scripts\Activate.ps1
py -3.15 -m pip install -r backend\requirements.txt
if (-not (Test-Path backend\.env)) { Copy-Item backend\.env.example backend\.env }
notepad backend\.env                    # replace the example values with your local values
```

For a new, empty database, apply the initial migration before starting the backend:

```powershell
py -3.15 -m alembic -c backend\alembic.ini upgrade head
```

If your database already has the `users` and `transactions` tables created by the earlier `create_all` setup, run this once instead of `upgrade head`:

```powershell
py -3.15 -m alembic -c backend\alembic.ini stamp head
```

Start the backend:

```powershell
py -3.15 -m uvicorn app.main:app --app-dir backend --reload
```

- API: <http://127.0.0.1:8000>
- Interactive API documentation (Swagger): <http://127.0.0.1:8000/docs>

### 3. Frontend

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

The frontend runs at the address shown in the terminal, usually <http://localhost:5173>.

### 4. Check the connection

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

When the database is available, the response contains `status: ok` and `database: connected`. If PostgreSQL cannot be reached, the endpoint returns **503**.

## Environment Configuration (.env)

Copy `backend/.env.example` to `backend/.env`, then replace the sample values with your local settings. The `.env` file contains secrets and is ignored by Git:

```env
DATABASE_URL=postgresql+psycopg://postgres:your-password@localhost:5432/cashflow
JWT_SECRET=replace-with-a-long-random-string
```

| Variable | Description |
|---|---|
| `DATABASE_URL` | SQLAlchemy connection string for PostgreSQL |
| `JWT_SECRET` | Secret key used to sign JWTs |

## API

All routes under `/api/v1/dashboard` and `/api/v1/transactions` require the `Authorization: Bearer <token>` header.

| Method | Route | Auth | Description |
|---|---|:---:|---|
| GET | `/health` | – | Checks the API and database connection |
| POST | `/api/v1/auth/register` | – | Creates an account |
| POST | `/api/v1/auth/login` | – | Authenticates the user and returns a token |
| GET | `/api/v1/dashboard/summary` | ✔ | Returns the user's financial summary |
| GET | `/api/v1/transactions` | ✔ | Lists the user's transactions |
| POST | `/api/v1/transactions` | ✔ | Creates a transaction |
| GET | `/api/v1/transactions/{transaction_id}` | ✔ | Returns a transaction |
| PUT | `/api/v1/transactions/{transaction_id}` | ✔ | Replaces a transaction's data |
| PATCH | `/api/v1/transactions/{transaction_id}` | ✔ | Partially updates a transaction |
| DELETE | `/api/v1/transactions/{transaction_id}` | ✔ | Deletes a transaction |

Example transaction:

```json
{
  "type": "expense",
  "amount": 42.50,
  "category": "Food",
  "transaction_date": "2026-11-20",
  "description": "Groceries"
}
```

Requests for a transaction belonging to another user return **404**, so its existence cannot be inferred.

## Security and Validation

- **Passwords**: stored only as Argon2 hashes, never as plain text.
- **Session**: expiring JWT; the frontend automatically logs the user out when the token expires.
- **Data isolation**: every transaction query is filtered by the user identified by the token.
- **Backend validation**: Pydantic schemas validate email, positive amounts, `income`/`expense` types, and dates; errors are returned as JSON with 4xx status codes.
- **Frontend validation**: form fields are checked before submission, and API errors appear as notifications.
- **Secrets**: `DATABASE_URL` and `JWT_SECRET` are read from `.env`, which is not tracked by Git.

## Milestones and Roadmap

Work is organized into GitHub milestones, each grouping issues with acceptance criteria. M1–M7 cover the first-semester MVP, while M8–M12 are planned for the second semester.

| # | Milestone | Scope | Status |
|---|---|---|:---:|
| M1 | Project Foundation | Repository structure, FastAPI + PostgreSQL, `/health`, React/Vite/Tailwind setup, local configuration, and migrations | 🟡 |
| M2 | Authentication | Registration / login, Argon2 hashing, JWT, protected routes, and session expiration | ✅ |
| M3 | Transactions | CRUD, per-user data isolation, validation, chronological history, and forms | 🟡 |
| M4 | Dashboard | Totals and balance, recent transactions, monthly comparison, spending by category, and charts | ✅ |
| M5 | UI/UX and Responsiveness | Mobile/desktop layout, loading/empty/error states, clear messages, and confirmations | 🟡 |
| M6 | Optional Features | Filter by category/date and CSV export | ⬜ |
| M7 | Quality and Delivery | pytest / Vitest tests, GitHub Actions CI, Docker Compose, and final documentation | ⬜ |
| M8 | Budgets and Goals | Category budgets, progress tracking, and savings goals | ⬜ |
| M9 | Recurring Transactions | Scheduled transactions, reminders, and duplicate prevention | ⬜ |
| M10 | Bank Accounts | Start with CSV import, then read-only synchronization through a compatible provider | ⬜ |
| M11 | Investment Portfolio | Track holdings and portfolio performance | ⬜ |
| M12 | Financial Insights | Explainable alerts and suggestions based on spending patterns | ⬜ |

Bank integration and investment tracking are future features. The application does not request or store online banking passwords. Planned suggestions are informational and explainable, not investment recommendations.
